# Draft Engine 設計書 (v1)

`docs/engine-roadmap.md` の Phase 1(新人プール生成)・Phase 2(ドラフト)と、
次シーズン開始ロスターへの反映までを対象にした設計。**v1 は完全ランダム**。
球団哲学ごとの指名ロジック(`docs/jbl-team-ai-design.md` §2)は v2 以降で差し替える。

**状態: 段階 1〜4 実装済み**(`include/DraftEngine.h`, `src/DraftEngine.cpp`, `app/draft_runner.cpp`)。

## 1. ゴール / スコープ

### やること(v1)
1. ドラフト候補(新人)をランダム生成する
2. 18 球団が 7 巡、ランダムに指名する(計 126 人)
3. 指名結果を次シーズンの開始ロスターに反映する
4. 結果を JSON で出力する(アプリで表示できる形)

### やらないこと(v1)
- 球団哲学による指名ロジック(v2)
- FA / トレード(roadmap Phase 3, 4)
- 加齢・成長 → `docs/progression-design.md` で実装済み(新人は毎年、天井に向かって成長する)
- ドラフト順の戦績連動(v1 は抽選順。差し替え可能にしておく)

## 3. データモデル(`include/DraftEngine.h`)

- `DraftConfig`: `season`, `seed`, `rounds`(7), `poolMultiplier`(1.5), `promotionMargin`(5)
- `DraftProspect`: `id`, `name`, `age`, `position`, `role`, `potential`, `readiness`, `overall`, `asPlayer`
- `DraftPick`: 巡・順・通算順位・球団・`prospectId`
- `RosterChange`: `Promoted`(昇格)/ `Released`(押し出された選手)/ `Minors`(二軍行き)
- `DraftResult`: プール・指名・変更一覧
- `DraftStrategy`: 指名ロジックの差し替え口。v1 は `randomStrategy()`

主な関数: `generateProspectPool()` → `runDraft()` → `applyDraftToRosters()`。
それぞれ単体でテストできる。乱数は `DraftConfig::seed` だけで決まる。

## 4. 新人プール生成 / ドラフト

### 4.1 プール生成
- 人数: `ceil(球団数 × 巡数 × 1.5)` = 189 人。指名されなかった選手が残る
- 投手 約 50% / 野手 約 50%。役割は `PLAYER_ARCHETYPES.md` のテンプレートから重み付き抽選
  (野手 15 種・投手 8 種。ポジションは役割ごとの候補から選ぶ)
- `readiness`(今の実力の段階): 正規分布 平均 52・標準偏差 8、30–80 に丸める。
  **62 = その役割の「標準的なレギュラー」**
- `potential` = `readiness` + 6〜18(上限 85)。v1 の能力値には使わず、将来の成長フェーズ用に出力する
- 各能力値 = 役割の目標値 + `(readiness − 62) × 0.8` + ノイズ(σ 3.5)、30–95 に丸める
- 年齢: 18〜22 歳(18:10% / 19:20% / 20:25% / 21:25% / 22:20%)
- 打席・投球の左右、打撃傾向、投手の球種(`arsenal`)も生成
- 名前: 姓・名の辞書から。プール内で重複せず、現役選手とも重ならない

### 4.2 ドラフト進行
- 順番: 球団をシャッフルして固定、**スネーク方式**(偶数巡は逆順)
- 指名: 残りプールから**一様ランダム**に 1 人(`DraftStrategy` で差し替え可能)
- 同じ `seed` なら結果が完全に一致する

## 5. ロスターへの反映(`applyDraftToRosters`)

制約: `Team` の人数構成は変えない。**新人が入る = 誰かが外れる**。

1. 各球団の指名選手を、総合値(`overall`)の高い順に処理する
2. **ベンチ(5 人)と救援(8 人)の選手だけが入れ替え対象**。打順と先発ローテーションは動かさない
3. 野手の新人はベンチ、投手の新人は救援のうち「まだ入れ替わっていない最弱の選手」と比べる
4. 新人の総合値が、その選手 + `promotionMargin`(5)以上なら昇格し、その選手はリリース
   - 投手は押し出した選手の役割(`pitcherRole` / `role`)を引き継ぎ、その役割で比較する
5. 昇格しなかった新人は二軍(`Minors`)扱い

総合値:
- 野手: `(contact×1.0 + power×0.9 + eye×0.7 + speed×0.5 + fielding×0.6 + arm×0.3) / 4.0`
- 投手: `(velocity×0.8 + control×1.0 + stuff×1.2 + stamina×w) / (3.0 + w)`
  (`w` は先発 0.7 / ロング 0.5 / それ以外 0.2)

`promotionMargin` の根拠(100 シードで計測):

| 基準 | 1 球団あたりの昇格数 |
|---|---|
| 0 | 3.2 |
| 3 | 2.3 |
| **5(既定)** | **1.8** |
| 8 | 1.1 |

## 6. 既知の制約と対策

- **新人が伸びない**: 加齢・成長(Phase 5)がないと能力は `readiness` のまま。
  昇格の基準を高めにして、「現役の控えより明確に上」の新人だけが入る状態にしている。
  `potential` は出力に含めてあり、Phase 5 でそのまま使える
- **リーグバランス**: 入れ替わるのはベンチと救援だけで、平均して 1 球団 1.8 人。
  レギュラーの能力は変わらないので、勢力図は大きく動かない
- **手書きロスターとの整合**: ロスターは `Teams.cpp` のまま。ドラフト結果は**実行時に差分適用**する(ソースは書き換えない)

## 7. 出力 JSON

`--out-dir` 配下の `draft/` に 3 ファイル。

- `draft.json`: `season`, `seed`, `rounds`, `picks[]`(巡・順・通算・球団・`prospectId`)
- `prospects.json`: 全プール(能力値・`potential` / `readiness` / `overall`・指名情報)
- `roster-changes.json`: `promoted` / `released` / `minors` の一覧(球団別に追える)

## 8. 実行方法とテスト

```
make -C app draft            # ビルド
./build/JojiDraftRunner --season 2027 --seed 1 --rounds 7 --out-dir <dir> [--margin 5]
make -C app test             # テスト
```

追加したテスト(`app/engine_tests.cpp`):
1. 同じシードなら全出力が一致し、別のシードなら変わる
2. 126 指名がすべて別の選手で、全球団が各 7 人。スネーク順になっている
3. プールの能力値・年齢が範囲内で、名前が重複せず、現役選手とも重ならない
4. 反映後も打順 9・先発 5・救援 8・ベンチ 5 が不変。打順と先発は同じ顔ぶれ。昇格数 = リリース数
5. 40 シードの平均で 1 球団あたりの昇格数が 0.8〜3.0 に収まる
6. `DraftStrategy` を差し替えられる(最良選手を取る戦略で 1 位指名が最高値)
